# Descoberta dos cases do portfólio

Esta pasta concentra o contexto necessário para escrever e estruturar os cases sem inventar informações. Cada projeto possui seu próprio formulário e novos projetos devem partir de `modelo-case.md`.

## Como usar

1. Abra o arquivo do projeto.
2. Revise os campos já preenchidos e corrija qualquer informação imprecisa.
3. Substitua `Resposta pendente.` pelas suas respostas.
4. Não é necessário escrever copy de portfólio: responda de forma direta e factual.
5. Depois da revisão, as respostas serão usadas para definir a estrutura visual, o modelo de dados e os textos do case.

Também é possível responder pela conversa usando o código da pergunta, por exemplo: `PAP-03: o objetivo principal era...`.

## Origem das informações

- **Portfólio:** informação encontrada no código ou nos textos atuais deste projeto. Ainda pode precisar de correção.
- **Repositório:** informação encontrada no `README.md` ou no `package.json` do projeto.
- **Informado por Lucino:** informação confirmada diretamente na conversa.
- **Resposta pendente:** contexto que não pode ser deduzido com segurança.

Uma dependência presente no `package.json` prova apenas que ela existe no projeto. Isso não prova que Lucino a escolheu, implementou ou domina.

## Limites de informação

- Não registrar nomes ou dados pessoais de clientes e colaboradores.
- Registrar apenas se o projeto foi autoral, colaborativo ou freelancer e qual foi a atuação de Lucino.
- Em projetos colaborativos, separar tecnologias do produto das tecnologias usadas diretamente por Lucino.
- Não copiar segredos, valores de variáveis de ambiente ou dados internos dos repositórios.
- Não transformar descrições do README em resultados ou métricas sem confirmação.
